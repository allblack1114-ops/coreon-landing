Common equipment-signal integration questions

Can an equipment alarm become a safety action?

Yes. An agreed event definition plus tenant, site and source scope allows an alarm to enter as a Safety Event candidate. Human review is required before accountable action.

Do you support OPC UA, Modbus/TCP and MQTT?

The normalized ingress contract is implemented for edge inputs identified with these protocols. Live device and gateway compatibility requires site testing of the network and tag model.

How are proprietary signals connected?

An approved, versioned Edge Mapping Profile converts source fields into the common event contract. Unapproved or hash-mismatched mappings fail closed.

Does the same event reach executive and audit output?

The event ID retains human review, owner, deadline, action, evidence, residual risk and approval history for scoped KPIs and an event Evidence Pack.

Ready to review an integration?

Customer-specific tenant, site and source scopes plus controlled credentials are required for operational connections.

Technical integration details

External signals are normalized as candidates, then promoted to official Safety Events only after authorized human review. COREON links the accepted event to ownership, due date, corrective action, evidence, residual-risk reassessment and final approval.

Integration candidates: PLC and control-panel faults, motor and pump condition, AMR/AGV and forklift state, CCTV analysis, gas and fire detection, access control and SCADA/MES/WMS/BMS alarms. Production scope depends on approved credentials, an agreed event contract and on-site interface validation; vendor or protocol compatibility is not pre-certified.
